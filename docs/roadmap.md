# Roadmap

The constitution is the stable meta plan. This roadmap is the part that changes: the order of
features and the review point after each. Each feature gets its own spec under `specs/`.

| # | Feature | Why this order | Status |
|---|---|---|---|
| 001 | **MCP Atlas** | Quickest unique win. A curated matrix of public MCP servers against the features of the current MCP authorization revision forces the data model to be right and is useful on day one. | Implemented, live at letsauth.eu; documentation pass recorded October 2026 |
| 002 | **Agent Auth Atlas** | The standards graph. Mostly data entry on the same model, plus one graph view. | Implemented, live at letsauth.eu/standards/ |
| 003 | **Delegation Chain Explorer** | The flagship. Step-through scenarios with the decoded token at each hop and attack toggles. Reuses features and revisions from 001 and 002. | Implemented, live at letsauth.eu/explorer/; three scenarios, eleven toggles (three of them replays for 005), `specs/003-delegation-explorer/` |
| 004 | **Scanner** | Automates what 001 did by hand. Passive checks on public metadata, graded report, nightly PR with observations. First and only backend. | Implemented; nightly scan running on Scaleway since October 2026 |
| 005 | **Breach Anatomy** | Each agent-auth vulnerability as a scenario replay plus a reproducible lab. Cheap once 003 exists. | Implemented; five entries, three replays, `specs/005-breach-anatomy/` (the lab is the explorer replay: a static site ships no exploit recipes) |
| 008 | **Discovery challenge check** | The first nightly run withheld grades for servers that publish no protected resource metadata at a well-known URL (Atlassian, Plaid, Stack Overflow), because the other allowed mechanism, a `resource_metadata` pointer in the 401 `WWW-Authenticate` challenge, needs a request the passive scanner does not make. One unauthenticated request per server to its MCP endpoint, reading only the challenge header, would fill `mcp.prm.www-authenticate` beside `mcp.prm.well-known`, so the atlas shows which mechanism each server offers, or both. It is the first request beyond well-known metadata, so the spec must justify it against the constitution before it runs. | Implemented; `specs/008-discovery-challenge/` records why it is still passive |
| 009 | **Server access and auth classes** | Today the atlas mixes servers anyone can connect to with ones that need an account, tenant or enterprise contract, and OAuth servers with API-key and open ones, using only the directory's unverified `authClaimed` label. Make access (public or closed) and auth (OAuth, API key, none) evidenced fields of their own; let the atlas group and filter by them; and let the scanner and the grade use them; drop the label. | Implemented; `specs/009-access-auth-classes/` |
| 010 | **Composable discovery strategies** | After the first nightly runs, several requirements stayed `unknown` for every server for the same few reasons: streamable HTTP servers answer the scanner's `GET` with 405 before authenticating, listed `/sse` endpoints had moved, metadata documents name no scopes, and the `scope` parameter the endpoint already sends was not read. Make each check an ordered list of strategies over the sources the probe found, make the endpoint request a ladder, read the scope challenge, and let the run summary flag stale URLs. | Implemented; `specs/010-discovery-strategies/` |
| 016 | **Visual redesign** | The site works but looks generated: boxes, shadows, glow, a slogan hero. Move it to one calm system shared with the maintainer's blog (flat surfaces, hairlines, two brand accents, Geist), with motion only where it explains a state, tighter byte and Lighthouse budgets, and a copy pass. No change to data, schema or URLs. | Implemented; work packages WP0 to WP8 merged, `specs/016-visual-redesign/plan.md` |
| 017 | **Neutral scan summary** | A letter grade ranks servers, which the atlas promises not to do. Replace the scanner's A to F grade with status counts per requirement level and the requests behind them. | Implemented; `specs/017-neutral-scan-summary/` |
| 018 | **Scanner pull requests on new findings** | Nightly runs repeated each other while earlier pull requests waited for review. Compare each run with the pending scanner pull requests as well as `main`, open a pull request only when something is new, and let an agentic workflow review the scanner's pull requests. | Implemented; owner setup outstanding, `specs/018-scanner-pr-automation/` |
| 019 | **Wider MCP coverage** | The atlas is only as useful as its rows and columns. Grow it in both directions: more public MCP servers, each with evidenced access and auth classes, and more feature checks, covering requirements of the MCP Authorization specification that are still read by hand or not at all, and the features each new revision adds. Passive checks come first. The longer aim is a full review that goes beyond public metadata; how to run one automatically and responsibly is still open, and its spec settles that against the constitution before any such check runs, as 008 did for the challenge request. | Planned |
| 020 | **Agentic correctness and completeness checks** | More rows and columns mean more cells that can be wrong, stale or missing. Extend the agentic review from 018 so agents check that each observation's evidence still says what the cell claims, that each citation resolves, which server and feature pairs have no observation yet, and which listed endpoints or revisions have moved. Agents propose by pull request and never merge; a maintainer reviews every change. | Planned |
| 021 | **Talks and presentations from the observations** | The dataset now holds dated observations across many servers and nightly runs. Turn them into talks and slide decks on what the atlas shows: which requirements servers meet, where they diverge and how that changed over time. Each figure on a slide is built from a dated snapshot of the data and cites the observations behind it, so a claim in a talk traces back to a cell. | Planned |

Numbers 006 (agents under EU rules) and 007 (changelog and newsletter) were dropped in November
2026 and are not reused. Numbers 011 to 015 are remediation specs for review findings, not
features, so they have no row here.

Review after each feature: does it still pass the three honesty tests, and did it make the shared
model better or worse?
